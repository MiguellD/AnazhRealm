# Karte K14 (Koordinator, 11.10., Fassung 2) — CI in zwei Stufen: Puls ≤ 2 min je Push, volle Batterie ≤ 12 min wo sie richtet

Kartenkopf: wie auftrag/karten-1110/K01.md (gilt). Risiko R1 (keine Wand fällt; sie läuft an anderer Stelle). Platz: leicht.
Schöpfer 11.10.: „der war früher unter 2 min, das wäre wieder genial.“

ZIEL:
- **Stufe P (Puls), jeder Push auf jedem Zweig:** Wanduhr ≤ 2 min (Median über 3 Läufe). Inhalt: node --check der geänderten JS,
  eslint auf geänderte Dateien, Prettier nur auf geänderte Dateien im format:check-Scope, die statischen Wände (`npm run check`:
  betriebsgesetz, altlasten, studio-vertrag, ci-deckung, constitution, source-probes …), die Byte-Verträge, wenn sie < 30 s kosten,
  und `npm run playtest:fast`. Was davon > 2 min treibt, wird gemessen und benannt — nie still gestrichen.
- **Stufe V (voll), die heutige Batterie (alle Gruppen):** läuft auf `integ-probe` und `main` (push), nachts (schedule), auf Abruf
  (workflow_dispatch) und bei jedem Commit, dessen Message `[ci voll]` trägt. Wanduhr ≤ 12 min durch Breite: Gruppen nach Median
  verteilen (Bin-Packing, größte Schritte zuerst; das Repo ist öffentlich — Standard-Runner gratis, bis 20 Jobs gleichzeitig).
- `[skip ci]` (WIP) überspringt beides.

SCHNITT (EINE Engstelle: .github/workflows/check.yml + gate:ci-deckung):
1. Laufzeit je Schritt aus den letzten 5 grünen Läufen per API (Median) → `spec/ci/ci-zeiten.json` (Daten, nie live in der CI gelesen
   außer vom Selbsttest).
2. check.yml: Job `puls` (immer, außer [skip ci]) und die Matrix `voll` mit Bedingung (Ref integ-probe/main, schedule, dispatch oder
   `[ci voll]` in der Commit-Message). Die Gruppen von `voll` neu verteilt (jede ≤ 11 min Median inkl. Setup).
3. gate:ci-deckung wandert mit: jeder Schritt in GENAU einer Stelle (puls ODER genau eine voll-Gruppe), jedes gate:* gedeckt, 0 Doppel,
   und neu die **Waage**: keine voll-Gruppe > 11 min Median, puls ≤ 2 min Median (aus ci-zeiten.json). Selbsttest: heutiges check.yml
   ROT mit Täter „playtest 1/3 trägt 24,4 min“, „check trägt Prettier 2,1 min auf dem ganzen Stamm“.
4. Merge-Regel (Koordinator, entscheidung.md §2.8): Puls grün an jedem Karten-Kopf; Karten mit Risiko R2/R3 tragen am letzten Push
   `[ci voll]` und brauchen die volle Batterie grün; R0/R1 brauchen den Puls, die volle Batterie richtet dann auf integ-probe je Merge.
   Diese Regel steht als Kommentar-Kopf in check.yml (EIN Satz).

im Commit-Rumpf); playtest-full (nachts) unberührt.
